# Security and correctness boundary

Nolane Plan treats external/model content as untrusted with respect to authority. A model cannot establish its own principal identity, grant itself authority, turn global kernel visibility into personal knowledge, convert modeled-support totality into open-world certainty, or commit a world fact by narration.

The reference implementation is not an identity provider, sandbox, generic scheduler, messaging platform or distributed consensus system. Hosts integrating real tools must provide principal identity/provenance and external capability/resource observations at the assurance level required by their risk policy, and must ensure tool calls cannot bypass the kernel's authority/dispatch fence.

Correctness boundaries include:

- host-grounded principal identity, recipient/time-grounded information observation and exact execution-principal binding;
- proof dependency capture, semantic/query freshness and positive-support vs blocking-invalidity separation;
- principal-relative non-anticipativity, sealed policy closure and advisory-only selection;
- adapter capability revision, durable dispatch-before-side-effect and evidence-bound reconciliation;
- joint control-plane schedulability when shared resource capacity is part of a policy guarantee;
- protected deadline-critical capacity that speculative planning cannot consume;
- bounded repeated handoff liveness with grounded deadlines and no rank-regression laundering;
- activation-time edge freshness/refresh for mutable generation, permission, reservation, writer and open-side-effect state;
- failure-set-relative option independence rather than fallback-count-based robustness;
- verified snapshot/journal prefix binding, canonical internal digests and fail-closed replay.

`PlanKernel.open()` is a correctness operation. Unsupported correctness-significant post-snapshot events fail closed; bounded migration never invents missing Wave-6 certificates; historical resource/job revisions are distinct from current logical pointers so stale authority cannot resurrect merely because an old object still exists.

Please report semantic authorization, information-scope, causal-cut, proof-capture, policy, schedulability, handoff-liveness, edge-freshness, common-mode independence, adapter-attestation, replay, reconciliation, freshness or postcondition bypasses with a minimal reproducer whenever possible.
